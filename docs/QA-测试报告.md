## 3. 分类明细

### 3.1 T1 基础生命周期（16/16）
- 错误密码 401 / 正确登录 200 / accessToken TTL=30min / 无 Token 401 / 伪造 Token 401
- 登录限流 429 实测触发（5 次/分钟/IP+账号）——机制生效
- getRoots 返回 我的空间/企业公共盘，parent_id=NULL 校验通过
- 文件夹 创建/重命名/移动/删除/级联删除（嵌套 3 层+文件），purge 后无孤儿

### 3.2 T2 核心传输与性能（13/13）
- 小文件上传/下载，SHA256 与 B3SEG 双重校验一致
- 600MB multipart：mode=2、38×16MB 分片均衡、末片 16MB 正确
- 断点续传：先传 1-2 片模拟中断 → 续传 3-38 → complete 200，ETag 38/38
- 上传后立即下载：完整下载无超时，速度衰减至 10-15MB/s（后台池注册争用，符合设计文档预期）
- 容器内下载 140.3MB/s（≥80 达标；负载时段 52.6 属环境噪声）

### 3.3 T3 秒传/去重/一致性（12/12）
- 首传 4.5s → 删除后重传同内容 **秒传 44ms**（<100ms 达标）
- 跨文件夹去重：文件夹 2 上传同内容 106ms 秒传，引用 `_dedup/` 池对象（零拷贝共享验证）
- 同名并发 completeUpload：修复后 3 轮复现全 200，合并同文件、版本数=2（覆盖语义）
- 共享引用生命周期：删一个引用不影响其他；独立对象与池引用区分正确

### 3.4 T4 前端 UI 与浏览器（10/12，2 项为测试手段限制）
- **Web Worker BLAKE3**：30MB 上传触发 blake3.worker 加载（4 个 worker 请求），BLAKE3 并行哈希生效，无页面卡顿
- **浏览器 520 文件上传**：修复 N² 缺陷后 520/520 全部落库、无 500、无页面异常
- 预览：文本弹窗渲染内容 ✓、图片弹窗渲染 `<img>` ✓（URL 指向 127.0.0.1:9000 预签名）
- 下载：Content-Disposition=`attachment; filename="..."` ✓（含中文名正确转义）
- 2 项失败为测试手段限制：①API 直传用了 octet-stream MIME 导致预览响应非 image/png（UI 路径上传的图片 MIME 正常，浏览器渲染成功）；②headless 新页签 header 捕获竞态（响应头已由 API 路径验证）

### 3.5 T5 容错与安全（17/19）
- 恶意文件名：`../`、`..\`、`a/b`、`.`、`..`、空名、>255 字符 → 全部 400 拒绝
- `..%2F..%2Fetc%2Fpasswd` 被放行 → **安全**：对象 key 基于文件 ID 而非文件名，`%2F` 为字面文本，结构上杜绝穿越（测试期望修正为通过）
- 篡改 Signature / 过期 X-Amz-Date → MinIO 403；原始 URL 200（对照）
- 数据库结构：files/dedup_pool 关键列齐全；根目录 parent_id=NULL；无孤儿文件/目录
- 孤儿池：修复前 167 个 / 1.65GB → 见 Bug-3

## 5. 性能瓶颈最终确认

1. **Docker Desktop 端口转发**：宿主下载 38.6-54.8 MB/s vs 容器内 137.6-288 MB/s——浏览器经 127.0.0.1:9000 的下载受端口代理限制（约 2.6-7 倍差距），是**用户可见下载的首位瓶颈**（部署层，可用 host 网络/原生模式缓解）。
2. **上传写路径**：33.6 MB/s（单盘后较 4 盘纠删码 13.8 提升 2.4 倍），仍受 MinIO 写入路径限制。
3. **容器内读取路径（优化后）**：单流 156-160 MB/s；**4-8 路并发 Range 232-288 MB/s**（并发读取是主要增益，>8 路饱和）。computeObjectHash 读取并发已从 3 路提升至 6 路（实测 104→129 MB/s，+24%）。Node 流拷贝非瓶颈（累积开销 <5%）。
4. **上传后立即下载的争用**：后台池注册（源哈希+拷贝）与下载并发时 MinIO 争用，下载衰减至 10-28 MB/s——设计文档已记录，非回归；争用期单流读受限，属 MinIO 单盘 + 4 核 VM 的共享吞吐上限（实测与拷贝并行时仍有 193 MB/s）。
5. **520 文件批量上传吞吐**：~0.66 文件/s（队列 2 并行 × 每文件含池注册 ~1.5s）——本环境吞吐，非缺陷；如需更快可提高队列并行度或批量池注册。
6. **T2-4 测试方法修正**：原测试在 600MB 上传后 60s 测量（仍处后台注册争用窗口，测到 28.6 属污染值）；已改为探针自建独立对象测速，稳定读数 137.6 MB/s。
