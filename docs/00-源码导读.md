# 源码导读（源码精读指南）

> 目的：给学习者一条从零开始的代码阅读路线，按「架构 → 请求链路 → 模块深度」递进，
> 每个文件标注职责、关键函数、阅读重点。配合 `docs/00-总体架构.md`、`docs/01-目录结构.md` 使用。
> 全文基于当前源码（v1.1.3）整理。

## 〇、30 秒总览

```
浏览器 (React, :8080)
   │ HTTP/JSON (+CSRF +JWT)
   ▼
nginx (静态资源 + 反向代理 /api)
   ▼
server (Node cluster 多进程, Express) ──► PostgreSQL（业务数据）
   │                                        │
   ├── MinIO（对象存储：文件内容，版本控制）  │
   └── Redis（目录列表/分享 缓存）            │
        （BLAKE3 哈希：去重/秒传/校验）        │
   ▲ 定时任务（回收站清理/配额重算/池GC/监控） │
   └──────────────────────────────────────────┘
```

- **技术栈**：Node.js + TypeScript + Express + React + Zustand + PostgreSQL + MinIO + Redis
- **部署形态**：Docker Compose 5 个容器（`docker-compose.yml`）
- **启动形态**：server 用 **cluster 多进程**（1 主 + N worker，`index.ts`）

## 四、一条请求的完整链路（示例：上传文件）

```
1. 浏览器：FileBrowserPage 选文件 → store/upload.ts 入队
2. utils/hash.ts：Web Worker 算 B3SEG 哈希（8MB 分片并行）
3. api：POST /api/files/upload/init {dirId, name, size, hash}
   → routes/files.ts → validateBody(zod)
   → services/file.service.ts initUpload
       ├── 权限校验 requireDirAccess
       ├── 同名查重（覆盖语义）
       ├── tryDedupHit：哈希命中去重池？→ 零拷贝秒传（返回 dedup:true）
       └── 未命中：创建 upload_sessions + 签发 MinIO 签名 URL
4. 浏览器：PUT 直传 MinIO（分片则 presign-parts 逐个 PUT）
5. api：POST /api/files/upload/complete
   → completeUpload：大小校验 → 服务端重算哈希校验 → 事务落库 files + file_versions
   → 注册去重池（异步拷贝对象入池 + 段哈希缓存）
   → 审计 writeAudit(upload_complete)
6. 目录列表缓存失效 → 前端刷新可见
```

## 五、值得精读的 5 段代码（进阶）

1. **`tryDedupHit`（file.service.ts）**——去重秒传的完整逻辑：池对象存在性、在线校验、
   未验证时的等待策略、零拷贝引用（dedup_ref）
2. **`completeUpload`（file.service.ts）**——上传落库事务：查重→新增/覆盖→版本记录→
   并发同名竞态（23505）重试
3. **`resolveDirAccess`（permission.service.ts）**——权限优先级叠加（管理员>个人>部门>公共>ACL>授权）
4. **`pump` 调度（store/upload.ts）**——上传队列并发控制（小文件 6 / 大文件 2），
   verifyAndBackfill 兜底补传
5. **`emptyTrash`（file.service.ts）**——清空回收站性能优化：批量删对象 + 批量删行 + 聚合 quota

## 七、常见疑问速答

- **BLAKE3 吗？** 是，但用 B3SEG 分段方案（`blake3-seg`），非标准 b3sum，见 `lib/blake3.ts`
- **sha256 字段存的是什么？** 实为 B3SEG 哈希（历史字段名沿用）
- **对象怎么存？** MinIO 版本控制，key=`{orgId}/{fileId}`，去重引用=`{orgId}/_dedup/{sha256}`
- **为什么删除后还能恢复？** MinIO 版本控制保留历史版本（DELETE 只加删除标记），
  本次 19879 个对象即靠撤销删除标记恢复
- **审计能查到什么？** 登录/上传/下载/删除/purge/恢复等全量操作（`audit_logs` 表），
  是排障与数据恢复的第一手依据
