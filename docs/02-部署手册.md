# 02 - 私有化部署手册

## 1. 硬件与软件要求

| 规模 | CPU | 内存 | 磁盘 | 说明 |
|---|---|---|---|---|
| 最小（<50 人） | 4 核 | 8 GB | 数据盘 ≥ 2 TB（SSD 或 SATA） | 单机，MinIO 单盘（默认，性能最优） |
| 推荐（50-500 人） | 8 核 | 16 GB | 按人均 5-20 GB 规划 | 单机单盘 或 4 盘纠删码（需 4 块独立盘）或 4 节点集群 |
| 生产集群 | 每节点 8 核/16 GB | 同上 | 每节点 2-4 块独立盘 | 4+ 节点，纠删码 4+4 |

- 操作系统：CentOS 7.9+ / Ubuntu 20.04+ / Windows Server 2019+（Docker Desktop）
- 软件：Docker Engine 20.10+（含 compose v2 插件），内核建议 4.9+（overlay2）
- 网络：服务器间内网互通；客户端可访问服务器 8080（Web）、9000（MinIO 签名 URL，如直连模式）

> 注意：MinIO 纠删码模式下**不要**使用 RAID 0/5 或单块大盘替代多盘；多盘 = 多数据卷。

## 2. 全新安装步骤（Linux）

```bash
# 1. 安装 Docker（离线环境见 docs/05-离线交付指南.md）
curl -fsSL https://get.docker.com | bash
systemctl enable --now docker

# 2. 获取代码（离线场景直接拷贝 offline-package 目录）
git clone <your-repo> minio-netdisk && cd minio-netdisk

# 3. 配置环境变量（关键步骤！）
cp .env.example .env
# 必改项：
#   POSTGRES_PASSWORD / MINIO_ROOT_USER / MINIO_ROOT_PASSWORD
#   JWT_ACCESS_SECRET / JWT_REFRESH_SECRET / COOKIE_SECRET
#   ADMIN_PASSWORD
#   MINIO_PUBLIC_ENDPOINT=本机内网IP或主机名（浏览器访问 MinIO 签名 URL 用）
# 生成强密钥：openssl rand -base64 48

# 可选增强配置（默认关闭/内置默认，按需在 .env 追加）：
#   性能:      WEB_CONCURRENCY=4             # cluster 进程数（默认 min(4,CPU)；1=单进程）
#              PG_POOL_MAX=60                # PostgreSQL 连接池上限
#   监控告警:  MONITOR_REDIS_MEM_PCT=80      # Redis 内存告警阈值 %
#              ALERT_DINGTALK_WEBHOOK=...    # 钉钉告警机器人（可选）
#              ALERT_WECOM_WEBHOOK=...       # 企业微信告警机器人（可选）
#              ALERT_WEBHOOK_URL=...         # 通用告警 webhook（可选）
#              ALERT_SMTP_HOST=...           # 告警邮件 SMTP（可选）
#   密码找回:  RESET_MAIL_HOST=smtp.qq.com   # 找回密码邮箱通道（配置后注册验证码/找回可用）
#              RESET_MAIL_PORT=465
#              RESET_MAIL_SECURE=true
#              RESET_MAIL_USER=<发件邮箱>
#              RESET_MAIL_PASS=<邮箱授权码>
#              RESET_SMS_WEBHOOK=...         # 短信网关 webhook（可选）
# 完整配置清单见 CHANGELOG.md 末尾「配置变更速查」。

# 4. 一键启动（首次会构建前后端镜像）
docker compose up -d --build

# 5. 验证
docker compose ps                     # 全部 healthy / running
curl http://127.0.0.1:8080/api/health # {"ok":true,"db":true,"minio":true}

# 6. 登录
#   Web:   http://<服务器IP>:8080
#   账号:  ADMIN_USERNAME / ADMIN_PASSWORD（.env 中配置，默认 admin）
#   首次登录后请立即在【个人中心】修改密码
```

## 4. 分布式 MinIO 集群部署（生产推荐）

以 4 台服务器为例，每台运行 1 个 minio 节点 + 1 个数据盘（或 2-4 块盘分别挂载）。

```bash
# 在 4 台服务器上分别放置编排文件（同一目录、同一 .env）
# 主节点（含 postgres/server/web）:
docker compose -f docker-compose.distributed.yml up -d --build

# 仅启动本机 minio 节点（节点 2/3/4）:
docker compose -f docker-compose.distributed.yml up -d minio-2   # 或 minio-3 / minio-4
```

要点：
- 集群要求节点数 ≥ 4（纠删码下限），节点间必须内网互通
- `.env` 中 `MINIO_PUBLIC_ENDPOINT` 填浏览器可达的 MinIO 地址（可用 Nginx 做 MinIO 负载均衡，将 9000 端口的请求分发到 4 个节点）
- 生产建议将 `deploy/minio-init` 只执行一次（幂等，可重复执行）
- 时钟同步（NTP）必须开启，所有节点时间偏差 < 15 分钟

### 4.1 集群扩容（横向扩展）

MinIO 集群**在线扩容**方式：

```bash
# 1. 新增节点 5、6，与旧节点使用相同 MINIO_ROOT_USER/PASSWORD
# 2. 新节点启动命令中加入全部节点：
minio server --address :9000 \
  http://minio-1/data http://minio-2/data http://minio-3/data http://minio-4/data \
  http://minio-5/data http://minio-6/data

# 3. 滚动重启旧节点（逐个，不要同时停多个）：
#    docker compose -f docker-compose.distributed.yml restart minio-1

# 4. 用 mc 校验集群健康：
mc admin info local
```

> 注意：扩容后纠删码从 4+4 变为 6+6（新写入数据按新策略分布，旧数据自动重平衡是异步的，属正常现象）。**不支持缩容**（减少节点会丢数据），规划容量时留足余量。

### 4.2 后端横向扩容（可选）

后端为无状态服务，多实例部署方式：
```yaml
# docker-compose 中增加 server-2 服务（同镜像同环境），前端 nginx upstream 两个后端
```
注意：登录限流为进程内存实现，多实例下限流计数不共享（可接受；如要求严格可升级为 Redis，接口已预留）。

## 5. 配置 Nginx 入口与 HTTPS（生产推荐）

业务已自带 Nginx（web 容器：静态资源 + /api 反代）。如需统一 HTTPS 入口或独立反代：

```nginx
# 前端容器之上再套一层企业 Nginx
server {
    listen 443 ssl;
    server_name netdisk.example.com;
    ssl_certificate     /etc/nginx/ssl/fullchain.pem;
    ssl_certificate_key /etc/nginx/ssl/privkey.pem;

    client_max_body_size 0;

    location /api/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto https;
    }
    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
    }
}
```
- 启用 HTTPS 时：`.env` 中 `TRUST_PROXY=true`、`MINIO_PUBLIC_USE_SSL=true`（如 MinIO 也走 TLS）
- 端口规划：8080 Web / 9000 MinIO API / 9001 MinIO Console（Console 生产建议仅内网访问或关闭）

## 6. 首次使用引导

1. 用管理员登录 → 管理台 → 部门管理：创建部门
2. 用户管理：创建用户（分配部门/角色/配额），初始密码自动生成
3. 员工登录后：个人空间上传文件 → 创建部门共享文件夹（部门管理员）→ 企业公共盘发布公共资料
4. 审计日志自动记录全部关键操作，可在管理台查询

## 7. 版本升级

```bash
# 后端/前端代码更新后：
git pull
docker compose up -d --build

# MinIO/PostgreSQL 镜像升级：
#   1. 先执行备份（见 docs/04-备份与恢复.md）
#   2. 修改 docker-compose.yml 镜像版本号
#   3. docker compose up -d
#   4. 验证健康检查通过
```
