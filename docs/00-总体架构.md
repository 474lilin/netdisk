# 00 - 系统总体架构

## 1. 分层架构

```
┌─────────────────────────────────────────────────────────────────────────┐
│  前端层 (Web)  React 18 + TypeScript + Vite + Ant Design                │
│  - 文件浏览/上传（分片断点续传）/预览/分享/回收站/搜索/管理台             │
│  - 通过 REST API 与业务服务交互；文件数据走【后端签发的临时签名 URL】      │
│  - 全部静态资源本地打包（pdf.js / docx-preview / SheetJS 离线渲染）       │
│  - 部署：Nginx 容器托管 + 反向代理 /api（浏览器同源，无跨域）             │
└───────────────┬─────────────────────────────────────────────────────────┘
                │ HTTPS/HTTP  REST (JSON + Bearer Token + CSRF Header)
┌───────────────▼─────────────────────────────────────────────────────────┐
│  业务服务层 (Node.js 20 + TypeScript + Express)                          │
│  - 认证：双令牌（Access+Refresh）、会话吊销、CSRF、bcrypt、LDAP 占位       │
│  - RBAC：企业/部门/用户三级权限解析（permission.service）                 │
│  - 文件服务：上传/下载/版本/回收站/移动复制/去重（file.service）           │
│  - 分享：内网链接 + 内部授权（share.service）                             │
│  - 组织/用户/配额/搜索/审计/定时任务                                      │
│  ★ 唯一持有 MinIO 密钥的服务；MinIO 细节（bucket/object key）完全封装     │
└───────────────┬─────────────────────────────────────────────────────────┘
                │ ① 元数据读写          ② 对象读写（签名 URL / S3 API）
┌───────────────▼───────────────┐   ┌────▼───────────────────────────────┐
│  PostgreSQL 16 元数据库层      │   │  MinIO 分布式对象存储层（社区版）    │
│  - 用户/组织/权限/目录/文件元数据│   │  - 文件实体、对象版本、分片          │
│  - 分享链接/审计日志/配额/会话  │   │  - 单节点单盘（推荐，命名卷最优）或 4 盘纠删码（需独立物理盘）或多节点集群    │
│  - 不存文件二进制（< 1KB 元数据）│   │  - 桶版本控制 + 生命周期清理          │
└───────────────────────────────┘   └────────────────────────────────────┘
```

## 2. 数据流

### 上传（分片，GB 级大文件）
```
浏览器 ──① POST /api/files/upload/init（校验配额/去重/签发）──▶ 业务服务 ──▶ PG 校验 + MinIO 创建 Multipart
浏览器 ◀── 返回 { sessionId, partSize } ── ② 逐批请求分片签名 URL
浏览器 ──③ PUT presigned-url?partNumber=N&uploadId=... ──▶ MinIO（直传，不经过后端/nginx）
浏览器 ──④ POST /api/files/upload/complete {sessionId, parts:[{partNumber,etag}]} ──▶ 业务服务
业务服务 ──⑤ MinIO completeMultipartUpload ──▶ 落库元数据 + 审计 + 配额 + 去重池
```

### 下载 / 预览
```
浏览器 ── GET /api/files/:id/download ──▶ 业务服务（权限校验 + 审计）
业务服务 ── presignedGetObject(1小时) ──▶ 返回临时 URL
浏览器 ── GET presigned-url ──▶ MinIO 直读（无密钥暴露）
```

### 去重秒传（节省 MinIO 空间，不限文件大小）
```
客户端 BLAKE3 分段并行哈希（B3SEG：8MB 分片 × Web Worker 多线程，任何大小 MB/GB/TB 均计算）→ 上传 init 携带
服务端查去重池（{org}/_dedup/{hash}，B3SEG 内容哈希，服务端 worker_threads 并行重算校验）：
  命中且哈希已验证 → 文件元数据【零拷贝引用】共享同一池对象（dedup_ref）→ 毫秒级秒传
  命中但未验证     → 等待后台校验完成或在线校验一次并缓存（verified），随后永久免验
  未命中           → 正常上传 → 完成后注册去重池（小文件服务端重算哈希可信；大文件后台异步校验池哈希）
池对象生命周期：引用计数维护——全部引用文件删除后才清理对象与池记录
同名同内容覆盖：直接秒传（不产生新版本）；同名不同内容：新版本（独立对象，不污染池）
说明：秒传本身为纯元数据操作，与文件大小无关；大文件代价仅在首次上传的本地流式哈希
     （本地磁盘读一遍）与首个重复的池哈希校验（后台完成，一次性）
性能优化：B3SEG 两级内存缓存（server/src/lib/segmentCache.ts，HASH_CACHE_MB 可调，默认 512MB）
   - 段数据缓存（LRU）：同一对象在同进程内重复校验直接命中 RAM，绕过 MinIO 读取
   - 段哈希缓存（32B/段，按内容哈希寻址）：上传校验通过后写入；池拷贝校验/恢复校验时
     对段哈希做纯 RAM 组合（毫秒级，实测 2.9s → 1ms），完全绕过 MinIO 读取瓶颈
   - 首遍哈希仍受 MinIO 读取路径限制（本环境实测 ~100MB/s，瓶颈为存储路径而非哈希本身）
```

## 3. 权限模型

| 角色 | 个人空间 | 本部门盘 | 企业公共盘 | 其他部门盘 | 管理能力 |
|---|---|---|---|---|---|
| 企业管理员(1) | 全权 | 全权 | 全权 | 全权 | 用户/部门/配额/审计 |
| 部门管理员(2) | 全权 | 读写删享 | 只读 | 无 | 部门目录 ACL |
| 普通员工(3) | 全权 | 只读 | 只读 | 无 | 个人分享 |

叠加规则：目录 **ACL**（对用户/部门/企业授予 读/写/删/享）+ **内部授权**（share_grants，
文件/目录授权给内部人员，可写/可删）→ 权限取并集。子目录继承父目录最小集。

## 4. 安全设计

| 威胁 | 对策 |
|---|---|
| MinIO 密钥泄露 | 密钥仅存后端环境变量；前端永远接触不到 accessKey/secretKey |
| 未授权访问对象 | 全部对象访问为后端签发的短期（默认 1h）签名 URL；权限校验在业务层 |
| CSRF | 双重提交 Cookie（`nd_csrf` Cookie + `X-CSRF-Token` 头）+ Refresh Cookie `SameSite=Strict` |
| 会话劫持 | Access(30m) + Refresh(30d) 双令牌；Refresh 存库可吊销、可轮换；修改密码吊销全部会话 |
| 密码泄露 | bcrypt(12) 加密存储；登录限流（5次/分钟/IP+账号） |
| 越权访问 | 服务端 RBAC 逐级校验；文件/目录操作全部走 requireDirAccess/requireFileAccess |
| 外网泄露 | 分享链接仅内网可达（部署层防火墙）；支持密码/有效期/次数限制；可随时撤销 |
| 传输安全 | 生产建议 Nginx 前置 TLS（见部署手册） |

## 5. 存储布局（业务层封装，前端不可见）

```
桶 netdisk-data（开启版本控制 + CORS + 生命周期规则）
├── {orgId}/{fileId}            文件对象（每次上传产生新版本，可回滚）
├── {orgId}/_dedup/{hash}       去重池（B3SEG 内容哈希，多文件零拷贝共享引用，引用计数管理生命周期）
└── （无其他任何暴露结构）
```

## 6. 关键组件清单

- 后端 26 个模块：认证、RBAC、文件、分享、配额、搜索、审计、回收站、版本、去重、定时任务
- 前端 10 个页面 + 8 个组件：文件浏览、上传队列、预览、分享、权限、版本、移动复制
- 部署：docker-compose（单机）/ docker-compose.distributed（4 节点集群）/ nginx 反代 / 离线包脚本
- 运维：备份（pg_dump + mc mirror）、恢复、健康检查、日志、定时清理策略
