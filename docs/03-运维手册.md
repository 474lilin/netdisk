# 03 - 运维手册

## 1. 服务清单与端口

| 服务 | 容器名 | 端口(内部) | 对外端口 | 说明 |
|---|---|---|---|---|
| web (Nginx) | netdisk-web | 80 | 8080（可改 WEB_PORT） | 前端 + /api 反代 |
| server | netdisk-server | 3000 | - | 业务后端 |
| postgres | netdisk-postgres | 5432 | - | 元数据库 |
| minio | netdisk-minio | 9000/9001 | 9000/9001（可改） | 对象存储 |
| minio-init | netdisk-minio-init | - | - | 一次性初始化 |

## 2. 常用命令

```bash
# 状态
docker compose ps
docker compose logs -f server          # 后端日志（JSON 结构化）
docker compose logs -f web             # Nginx 日志
docker compose logs --tail=200 minio   # MinIO 日志

# 重启
docker compose restart server

# 停止 / 启动
docker compose down                    # 停止（数据卷保留）
docker compose down -v                 # 危险！删除数据卷（含全部数据）
docker compose up -d                   # 再次启动

# 进入容器排查
docker exec -it netdisk-postgres psql -U netdisk -d netdisk
docker exec -it netdisk-minio mc alias set local http://127.0.0.1:9000 <user> <pass>
```

## 3. 健康检查

```bash
curl http://127.0.0.1:8080/api/health
# {"ok":true,"db":true,"minio":true}

# 容器健康状态（docker compose 已内置 healthcheck）
docker inspect --format '{{.State.Health.Status}}' netdisk-server
docker inspect --format '{{.State.Health.Status}}' netdisk-postgres
docker inspect --format '{{.State.Health.Status}}' netdisk-minio
```

## 4. 日志说明

- 后端：JSON 结构化日志（时间/级别/消息/字段），`docker compose logs -f server`
- 关键事件：启动引导、桶初始化、回收站清理、配额重算、审计写入失败等
- 审计日志（业务）：管理台「审计日志」可查（login/download/delete/share 等），存于 PG `audit_logs` 表，默认保留 365 天自动清理（AUDIT_RETENTION_DAYS）

## 5. 故障排查

| 现象 | 排查步骤 |
|---|---|
| 浏览器打不开 | ① `docker compose ps` 是否 running ② `curl :8080/api/health` ③ 防火墙放行 8080 |
| health 返回 db:false | ① `docker compose logs postgres` ② 磁盘是否满 ③ 检查 .env 中 POSTGRES_PASSWORD 与数据库初始化一致 |
| health 返回 minio:false | ① `docker compose logs minio` ② 检查 MINIO_ROOT_USER/PASSWORD ③ minio-init 是否成功（`docker compose logs minio-init`） |
| 上传失败/401 | ① 浏览器 F12 看签名 URL 是否可访问 ② 检查 MINIO_PUBLIC_ENDPOINT 是否浏览器可达 ③ 检查 MinIO 桶 CORS（`mc cors get`） |
| 分片上传提示大小不一致 | 客户端与服务端 PART_SIZE 不一致（升级后需重启浏览器页面） |
| 配额报错但没用满 | 定时配额重算（每日 3 点）；或手动执行 `UPDATE users SET used_bytes=...` 后重启 |
| 502 Bad Gateway (web) | server 容器未就绪：`docker compose logs server` 看启动错误 |
| PostgreSQL 密码错误 | 首次初始化后改密码不会更新已有库；需按 04-备份与恢复.md 重建或改回原密码 |
| 文件下载 403 | 签名 URL 过期（默认 1h），重新点击下载即可；大下载建议通过客户端工具 |

## 6. 定时任务（后端内置，可配置）

| 任务 | 周期 | 说明 | 配置 |
|---|---|---|---|
| 回收站自动清理 | 每天 02:00 | 超过 TRASH_RETENTION_DAYS 的文件/目录彻底删除 | TRASH_RETENTION_DAYS |
| 过期分享清理 | 每小时 | 过期分享链接自动撤销 | - |
| 配额重算 | 每天 03:00 | 兜底校正用户已用容量 | QUOTA_RECOMPUTE_CRON |
| 审计日志清理 | 每天 04:00 | 删除超期审计 | AUDIT_RETENTION_DAYS |
| 孤儿上传会话清理 | 每天 02:30 | 中止 7 天未完成的上传 | - |
| MinIO 非当前版本清理 | 持续 | 桶生命周期规则：非当前版本 30 天过期 | deploy/minio-init/init.sh |

## 8. 存储性能调优（实测数据，2026-08）

本机 4 核 Docker VM 实测（256MB 对象，吞吐受环境限制，供容量规划参考）：

| 配置 | 写(PUT) | 流读 | Range读(8MB×4) | 服务端拷贝 |
|---|---|---|---|---|
| 4 盘纠删码 + N盘 bind mount | ~18 MB/s | ~190 MB/s | ~123 MB/s | ~21 MB/s |
| 单盘 + 命名卷（VM 内） | ~32 MB/s | ~101 MB/s | ~101 MB/s | ~104 MB/s |
| 单盘 + N盘 bind mount | ~20 MB/s | ~83 MB/s | ~89 MB/s | ~38 MB/s |

结论与建议：
- **单节点部署去掉纠删码**：单机多"盘"若为同一物理盘/同一挂载，纠删码只有 I/O 放大、无冗余收益。
  数据目录改为单目录（`server /data1`）；纠删码仅在多块真实独立物理盘上才有意义。
- **优先命名卷而非 bind mount**：VM 内 ext4 命名卷的服务端拷贝快 5 倍（104 vs 21 MB/s），
  对去重池注册（大文件拷贝入池）收益显著。大容量场景可换 SSD 数据盘。
- **B3SEG 段缓存**（HASH_CACHE_MB，默认 512MB）已内置：重复校验（池注册/恢复/内联）命中内存
  毫秒级完成；首遍哈希仍受存储路径限制，提升存储即提升首遍与上传。

数据盘迁移（MinIO 单盘示例）：
```bash
# 1. 停服
docker compose stop minio server
# 2. 修改 docker-compose.override.yml：单盘命名卷或新数据盘 bind
# 3. 拷贝旧数据（如旧数据在 4 目录，需先重建单盘格式后重新上传；元数据在 PG 不迁移）
docker compose up -d
```
> 注意：MinIO 纠删码数据不能跨拓扑直接迁移（4 盘→1 盘需重建桶内对象）；
> 文件元数据存于 PG（不随 MinIO 迁移），重建对象后通过覆盖/秒传恢复内容即可。

## 9. 安全加固清单

- [ ] 所有默认密码已修改（postgres/minio/admin/JWT/COOKIE）
- [ ] MinIO Console（9001）仅内网访问或关闭端口映射
- [ ] 前端统一 HTTPS（见部署手册第 5 节），TRUST_PROXY=true
- [ ] 企业防火墙限制 8080 仅办公网段可达
- [ ] 定期备份（每日），备份文件异地存放
- [ ] 审计日志定期导出归档（合规需要）
- [ ] 员工离职：管理台禁用账号（会话即时失效，因为每次请求实时校验 status）
- [ ] 开通密码找回：配置 `RESET_MAIL_*`（邮箱）或 `RESET_SMS_WEBHOOK`（短信），
      并确保用户已在管理台维护 email/phone
- [ ] 重要账号建议开启 2FA（个人中心 → 双重认证，TOTP 扫码）

## 10. 监控告警运维（v1.0.4+）

内置监控每 5 分钟自检（`MONITOR_CHECK_CRON` 可调），覆盖：

| 指标 | 触发条件 | 告警级别 |
| --- | --- | --- |
| Redis 内存 | 使用率 ≥ `MONITOR_REDIS_MEM_PCT`(默认80%) | critical |
| 缓存命中率 | 采样 ≥200 且命中率 <40% | warn |
| 定时任务停滞 | 每日任务 26h / 每小时任务 2h 无成功执行 | critical |
| 调度器存活 | `monitor_job_runs` 全空 | critical |

- 查看状态：`curl http://127.0.0.1:8080/api/health`（附 `monitor` 摘要）；登录后
  `GET /api/monitor/status`（任务执行记录 + 活动告警）；管理员 `POST /api/monitor/check` 手动自检
- 告警持久化：`monitor_alerts` 表（active=TRUE 为未恢复；恢复自动置 FALSE）
- 通知渠道：钉钉 / 企业微信 / 通用 webhook / 邮件（`ALERT_*` 配置，见 CHANGELOG 配置速查）；
  告警首次触发与恢复时各通知一次，持续告警不重复
- 注意：机器休眠期间定时任务会停滞并触发 `job_stale` 告警——唤醒后下个周期自动恢复并解除，
  属正常现象，无需干预

## 11. 账号安全运维（v1.0.9+）

- **登录锁定**：连续 5 次失败锁定 30 分钟（`users.locked_until` 到期自动解锁）；
  手动解锁：`UPDATE users SET locked_until=NULL, failed_attempts=0 WHERE username='xx'`
- **2FA**：用户个人中心自助开启/关闭（关闭需动态码+密码）；忘记动态码时管理员可
  `UPDATE users SET twofa_secret=NULL, twofa_enabled=false WHERE username='xx'` 强制解除
- **设备管理**：个人中心「登录设备」可查看/下线其他设备（吊销对应会话）
- **异常登录**：登录响应带 `risk` 标记（IP/UA 变化），前端提示；审计日志 action=login 可查

## 12. 磁盘与 vhdx（Windows/WSL2 部署）

- Docker 删除数据后 WSL2 `docker_data.vhdx` **不会自动收缩**，C 盘可能虚高：
  ```powershell
  # 退出 Docker Desktop 后：
  wsl --shutdown
  diskpart /s <<< "select vdisk file=`"C:\Users\<用户>\AppData\Local\Docker\wsl\disk\docker_data.vhdx`"`nattach vdisk readonly`ncompact vdisk`ndetach vdisk`nexit"
  ```
- 定期清理：`docker image prune -f`、`docker builder prune -f`、`docker volume prune -f`
  （先确认无容器使用：`docker ps -a --filter volume=<名>`）
