# 04 - 备份与恢复方案

## 1. 备份对象

| 数据 | 位置 | 备份方式 | 重要性 |
|---|---|---|---|
| 元数据（用户/权限/文件清单/分享/审计/配额） | PostgreSQL `netdisk` 库 | pg_dump | ★★★ 必备份 |
| 文件实体（含版本） | MinIO `netdisk-data` 桶 | mc mirror | ★★★ 必备份 |
| 配置（.env / compose / nginx） | 服务器目录 | 文件拷贝 | ★★ |

> 两个必须同时备份：只有元数据没有对象 = 文件列表存在但内容缺失；
> 只有对象没有元数据 = 无法知道文件归属。两者缺一不可。

## 2. 一键备份（推荐）

项目已提供脚本（Linux）：

```bash
# 手动备份（默认到 ./backups/时间戳）
./deploy/scripts/backup.sh /data/backups/netdisk

# crontab 每日 02:30 自动备份 + 保留最近 14 份
crontab -e
30 2 * * * /opt/minio-netdisk/deploy/scripts/backup.sh /data/backups/netdisk >> /var/log/netdisk-backup.log 2>&1
```

备份产物结构：
```
backups/20250101_023000/
├── postgres.dump          # 元数据（pg_dump 自定义格式）
└── minio/                 # 对象数据（mc mirror 全量镜像）
```

**异地/多副本建议**：备份目录挂载到另一台服务器（rsync/云存储/NAS），至少保留 14 天 + 月度归档。

## 3. 恢复演练（每季度至少一次）

```bash
# 1. 停止业务（避免写入）
docker compose stop server web

# 2. 恢复数据库
./deploy/scripts/restore.sh /data/backups/netdisk/20250101_023000

# 3. 启动
docker compose start

# 4. 验证：登录 Web，抽查文件可下载、权限正确
```

### 恢复注意事项
- 恢复会**覆盖**现有数据，务必在停服状态下执行
- pg_restore 需要同版本或更高版本 PostgreSQL
- MinIO 恢复后桶版本控制/CORS/生命周期规则需重新确认（脚本已处理建桶，但恢复后用 `mc version info` 复核）

## 4. 单表/局部恢复（高级）

```bash
# 只恢复用户表
docker exec netdisk-postgres pg_restore -U netdisk -d netdisk \
  --clean --if-exists --no-owner -t users /path/to/postgres.dump

# 只恢复某个对象的文件（用 mc 按前缀）
mc mirror --overwrite local/netdisk-data/{orgId}/{fileId} /restore/target
```

## 5. 备份策略建议

| 环境 | 频率 | 保留 | 说明 |
|---|---|---|---|
| 开发/测试 | 每周 | 4 份 | - |
| 生产（<100人） | 每日 | 14 天 | 每日全量（mc mirror 支持增量语义） |
| 生产（>100人） | 每日 + 每季度 | 14 天 + 12 个月 | 季度归档异地存放 |

- mc mirror 第二次运行会增量同步（按对象大小/时间判断），日常备份成本可控
- 大文件场景建议错峰备份（凌晨业务低谷）

## 6. MinIO 单机 vs 集群的备份差异

| 模式 | 冗余能力 | 备份要求 |
|---|---|---|
| 单机单盘（默认，命名卷） | 无冗余（单盘故障即丢数据） | 每日备份**必须**（唯一防线） |
| 单机 4 盘纠删码 | 任意 2 盘故障不丢数据 | 仍需每日备份（机房/服务器整体故障无法靠纠删码恢复） |
| 4 节点集群 | 任意 2 节点故障不丢数据 | 同上，异地备份必须 |
